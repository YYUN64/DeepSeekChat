## 新增（v1.9.1）

- **多选照片**：输入框左侧「+」→「添加图片」一次可选多张（`PickMultipleVisualMedia`，API 33+ 走系统照片选择器，Android 12 等低版本自动回退到 SAF 多选）；每张都走原来的 1600px 缩放 + EXIF 转正 + JPEG 88；一条消息最多 6 张，超出的丢弃并提示「最多还能添加 N 张」；缩略图可逐个删除
- **添加任意文本文件**：输入框左侧「+」→「添加文件」，可读取 .txt/.md/.json/.csv/.log/.xml/.yaml/代码等文本文件；含 NUL 字节判定为二进制并拒绝（提示先转成文本）；单文件超过 256 KB 截断并标注「…（已截断，原文件 N KB）」；最多同时附 5 个、合计 1 MB；附件以 chip（文件名 + 大小）显示，可删除
- **文件内容不再铺在气泡里**：用户消息只显示附件 chip（文件名 + 大小，截断时注明），正文只有自己打的字；文件内容存在消息的 `fileBlocks` 里**只发给模型**。会话 JSON 里持久化 `attachments` 元数据 + `fileBlocks` 文本（不存二进制）；老会话（1.9.0 及以前把内容内联在正文里的消息）显示与发送都保持原样；「复制对话」只写 `【附件：名字（大小）】`，不导出内容
- **中途插话 = 排队**（对齐 DSH）：生成中按发送不打断当前生成，消息排进队列——输入框上方显示「排队中：<前 30 字>…」，右侧 × 可取消，支持多条按顺序；当前生成结束（成功/失败/停止/超时）后自动发出队首，依次直到队列空；排队发出的一条走正常流程（图片/文件/MCP 工具/上下文都照常）。停止键只停当前生成；切会话或新建对话会清空队列并提示。队列只在内存里，进程被杀即丢（不做持久化）
- **输入区按钮**：空闲时右侧只有一个发送键；生成中变成两个并排按钮——左「停止」（只停当前生成）、右「发送」（点击 = 排队），尺寸与配色沿用现有按钮
- **后台保活**：前台服务通知覆盖整轮，文案按阶段变（`正在连接 MCP…` / `正在生成回答…` / `正在调用工具：run_command` / `正在整理答案…`），仍是 IMPORTANCE_MIN 静默无按钮通知；生成与 MCP 工具调用改跑在应用级 scope（`ChatEngine`），Activity 被回收、最近任务被划掉都不再中断；`ChatService` 加 `stopWithTask="false"`，划掉任务不停服务；界面改用共享的 ChatViewModel，回到 App 仍是同一个会话与同一段输出。进程真被系统杀死时依旧靠流式检查点保住已输出的部分
